# SovereignStream — Adaptive Network Routing (Phase 5)

Related: [REPLICATION.md](REPLICATION.md) · [POLICY.md](POLICY.md) · [DEPLOYMENT.md](DEPLOYMENT.md) · [SECURITY.md](SECURITY.md)

## 1. What it does

Each replication flow (source region → target region) may have several egress **paths** (`DIRECT`, `PEERING`, `RELAY`). The source agent measures every path, decides which is *eligible*, scores the eligible ones, and sends batches over the chosen one. The receiver independently re-checks that the declared path is legal.

Order of decisions (never reversed):

1. **Eligibility (policy).** Hard constraints; a score can never override them.
   `PATH_TRANSIT_ZONE_NOT_ALLOWED`, `RELAY_REGION_NOT_ALLOWED`, `PATH_NOT_ENCRYPTED` (CONFIDENTIAL/RESTRICTED), `PATH_DISABLED`, `PATH_LOOP`.
2. **Usability (health).** Circuit breaker state, stale or invalid samples.
3. **Scoring.** Weighted, deterministic: latency 0.30, loss 0.30, backlog-drain delay 0.30, cost 0.10, each normalised.
4. **Switching rules.** Observation window, hysteresis (25 % better needed), sustained hold, cooldown. An unusable current path is replaced immediately. A `fallback` path is used when it is the only usable one. If nothing is usable the state is `NO_USABLE_PATH`.

A route change never touches checkpoints. The same (flow, partition) checkpoint and the receiver's ordering gate (`prev_offset`) apply on every path, so a switch causes at most re-sending of unacknowledged batches (at-least-once, see REPLICATION.md).

## 3. All paths down

- Remote replication pauses (`PAUSED_NO_ROUTE`); consumers' local persistence in the active region continues.
- Backlog is measured from the source log (end offset − checkpoint); nothing is queued in memory beyond the bounded pending batches.
- Backlog is reported to the engine every ~2 s. Above the soft limit the state is `SOFT`; above the hard limit it is `HARD`. For topics whose `lag_breach_action` is `REJECT_WRITES`, the gateway answers `503 REPLICATION_BACKPRESSURE` while the backlog is `HARD`.
- On recovery the agent resumes from the checkpoint and drains.

## 4. Operations

```
infrastructure/chaos/latency.sh   <proxy> [ms=400] [jitter_ms=0]     proxy = <src>-<dst>-<direct|peering|relay>, e.g. a-b-direct
infrastructure/chaos/jitter.sh    <proxy> [base_ms=50] [jitter_ms=100]
infrastructure/chaos/bandwidth.sh <proxy> [KB_per_s=50]
infrastructure/chaos/loss.sh      <proxy> ...    (probabilistic connection resets, not packet loss)
infrastructure/chaos/reset.sh     <proxy> ...
infrastructure/chaos/disconnect.sh <proxy>... | --pair <a|b|c> <a|b|c>
infrastructure/chaos/recover.sh   <proxy>... | --pair a b | --all
infrastructure/chaos/list.sh
```

Proxy ports: `18000 + 100*src + 10*dst + path` (regions a=1, b=2, c=3; direct=1, peering=2, relay=3). Paths are seeded from `policy/config/seed-paths.json` (generated by `chaos/gen_paths.py`) and can be changed with `PUT /api/v1/network/paths/{id}` (admin, audited). Route changes are audited with operation `ROUTE_SWITCH`, enforcement point `ROUTING`.

Tunables (replicator env): `SS_PROBE_INTERVAL_S`, `SS_ROUTE_MIN_OBSERVATION_S`, `SS_ROUTE_HOLD_S`, `SS_ROUTE_COOLDOWN_S`, `SS_ROUTE_HYSTERESIS`, `SS_BREAKER_FAILURES`, `SS_BREAKER_OPEN_S`.

## 5. Evidence: tested vs simulated vs not done

**Tested (automated):**
- `policy/tests/test_routing.py` — 22 deterministic and property tests of eligibility, scoring, breaker, selector, backlog.
- `policy/tests/test_routing_integration.py` — prohibited route never used; security requirement (unencrypted path rejected for restricted data); switch to path B on injected degradation with unchanged checkpoint and preserved order and an audit record; small fluctuation does not flap; circuit breaker with recovery probing; all-paths-down with bounded backlog, backpressure and recovery; ordering across route changes. A randomized-loss stress test is opt-in and supplementary.
- Receiver rejects missing, unknown or illegal path with `403 PATH_NOT_AUTHORIZED` (Phase 4 test_13 updated accordingly).

**Simulated:**
- All network faults are Toxiproxy on Docker networks. "Loss" is emulated by probabilistic connection resets, not packet loss. A relay is modelled as a separate proxy to the same receiver, not a real intermediate region.
- Transit zones and encryption flags are registry declarations; nothing verifies the physical route or TLS on the proxy hop.

**Observed once on one machine (not benchmarks):** a switch took 13.0 s after injecting 400 ms latency plus 20 KB/s bandwidth on `a-b-direct`. Backpressure engaged after 81 records against a hard limit of about 60; the overshoot is bounded by the 2 s report interval plus the 1 s gateway cache.

**Known limitations / not done:**
- Probes are application-level HTTP, not ICMP.
- Backlog bytes are an estimate (records × observed average size); there is no real disk-usage monitoring.
- Route state lives in agent memory and is rebuilt after restart.
- A reporter that stops reporting leaves the last state (a stale HARD still blocks writes).
- Only `max_inflight=1` was tested.
- No production WAN, real TLS between regions, or multi-host testing.
