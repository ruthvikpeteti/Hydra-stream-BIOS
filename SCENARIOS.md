# SovereignStream — End-to-end scenarios (Phase 8)

Each of the eleven required scenarios is checked by automated tests against the live stack (three regions, coordinator, gateways, policy engine, replicators).
Pass/fail per scenario is in [TEST_RESULTS.md](TEST_RESULTS.md), generated from the JUnit files of the last campaign; this page says what each scenario
asserts, which test does it, and **what it does not prove**. Run them with `ci/run_scenarios.sh` (fresh stacks, destructive).

| # | Scenario | Tests | Not proven / honest notes |
|---|---|---|---|
| 1 | Normal operation | `test_scenarios.py::test_scenario_1_…` | **Interpretation:** an EU-restricted topic can only live in A and B (region C is US-only in this registry), so it replicates A→B and C is prohibited; replication to *both* B and C is shown with a GLOBAL-zone topic. Matching event ids and per-partition order are compared from the logs. Duplicates would not fail this test (at-least-once) |
| 2 | Residency rejection | `test_scenarios.py::test_scenario_2_…`, `test_replication.py::test_12_…`, `test_routing_integration.py::test_a_…` | Source side = the policy engine (and the source agent's per-flow check); receiver side = the target region's own agent refusing a hand-built batch. Both audited; the audit chain verifies. "The law" is whatever the operator declared in the registry: the engine does not decide legality (POLICY.md) |
| 3 | Network degradation | `test_routing_integration.py::test_path_b_is_selected_when_a_degrades_…` | Latency and bandwidth are injected with Toxiproxy on a proxy path, not on real WAN links. Checkpoints are compared before and after the switch; order verified |
| 4 | All paths unavailable | `test_routing_integration.py::test_all_paths_down_…` | Local publishing continues; the backlog is bounded by configured thresholds and backpressure is applied to topics whose policy says `REJECT_WRITES`. **"Within disk limits":** disk usage is not monitored; the bound is the backlog threshold, not free disk |
| 5 | Broker failure | `test_dr.py::test_01_…`, `test_02_…`, `infrastructure/tests/test_c_*.sh`, `test_d_*.sh`, `test_e_*.sh` | Only region A has more than one broker. Consumers re-read through the gateway (no consumer-group rebalance is exercised: the gateway keeps offsets itself) |
| 6 | Primary regional failure | `test_dr.py::test_05_…`, `test_08_…` | A is stopped with `docker stop`. B promoted at epoch 2, A fenced (coordinator + Kafka-level), clients switch gateways, consumers resume at the same offsets (checkpoints show identity translation) |
| 7 | Secondary regional failure | `test_dr.py::test_06_…`, `test_07_…` | B→C replication of post-promotion events, then B killed **with A already lost**: the coordinator keeps its quorum through the two witnesses and C is promoted after a deliberate controller crash and resume. The "actual recovery position" is the measured count of acknowledged events missing from C |
| 8 | Stale tertiary replica | `test_dr_stale_c.py` | C is cut off from B for longer than the 30 s lag budget, B then fails: the controller reports `NO_ELIGIBLE_TARGET`, no region may write, a degraded-RPO request is refused because the deployment forbids it, and the events C would have lost are counted. The lag figure is a bound with ~10 s resolution (DR.md) |
| 9 | Split brain | `test_dr_failback.py::test_01_…` | The old primary stays **alive and reachable to the test client**, its gateway is disconnected from the coordinator network, and a false-positive detector declares it dead. It acknowledged writes until its lease ran out (before B was activated) and none after; B acknowledged none before activation. One authority at every sampled instant |
| 10 | Coordinator failure | `test_dr.py::test_03_…`, `test_09_…` | 3 of 5 members down: no state change, the healthy active region stops writing when its lease expires, writes resume when quorum returns. With both witnesses and C lost too (2 of 5 alive) while the active region dies: no promotion |
| 11 | Failback | `test_dr_failback.py::test_02_…`–`test_04_…`, `test_dr.py::test_08_…` | Restored A stays fenced (gateway and Kafka), its divergent suffix is quarantined (never merged), an explicit approval is required, B is fenced before A is activated, end offsets and the last 50 event ids per partition are compared. Replicas are rebuilt afterwards (fewer replicas than policy during that time) |

Cross-cutting: every scenario ran against asynchronous replication. None of them demonstrates zero data loss; scenarios 6, 7 and 9 *measure* the acknowledged-but-absent
events instead (zero when replication was current, 94 in the case where the paths were cut first: see TEST_RESULTS.md and DR.md §9.2).
