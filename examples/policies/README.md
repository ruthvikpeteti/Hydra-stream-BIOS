# Example policy configuration

```
KEY=$(grep ^SS_GATEWAY_API_KEY ../../infrastructure/.env | cut -d= -f2)
curl -s -X POST localhost:8080/api/v1/topics -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     -d "$(python3 -c 'import json,sys;d=json.load(open("eu-restricted-topic.json"));d.pop("_comment");print(json.dumps(d))')"
# then start replication (policy engine, writer role):
WK=$(grep ^SS_POLICY_WRITER_KEY ../../infrastructure/.env | cut -d= -f2)
curl -s -X POST localhost:8090/api/v1/replication/topics/payments.eu/start -H "X-Service-Key: $WK" -H 'Content-Type: application/json' -d '{"partitions":3}'
```

The regions, their legal zones and the links between them (the registry the policy engine is seeded with) are in
`policy/config/seed-registry.json`; the network paths in `policy/config/seed-paths.json` (generated by `infrastructure/chaos/gen_paths.py`).
A policy never overrides the law: it records what the operator declared, and the engine refuses anything outside it (POLICY.md).
